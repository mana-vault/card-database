# 貢献するには

カードデータベースをよくするご協力、ありがとうございます。

## 貢献のかたち

このリポジトリには、`data/` のカードのデータ、`schema/` のその JSON Schema、`docs/` の設計文書を置くので、貢献もそのどれかに当たります。

| 貢献 | 内容 |
| --- | --- |
| `カード`のデータ | `data/card/li/lightning-bolt.json` のように`カード`のファイルを書きます。参照する部品の値は `data/component/` の一覧にあります |
| `プリント`のデータ | `data/print/ja/mh3/170.json` のように、`プリント`ごとに一つのファイルを書きます。属するセットが、すでに登録してある必要があります |
| 公式の訂正 | Wizards of the Coast の訂正が入ったら、値を直すとともに、その物の `history` へ記録を追記します。記録の形は、スキーマに従います |
| スキーマと文書 | `schema/` や `docs/` を変えます。設計がまだ決まっていない点は、変更の前に Issue で出します |

## 手順

1. 触れる`カード`やセット、`翻訳`が、いまどうなっているかを確かめます。
2. ファイルの形式と置き場所は [design.md](design.md) に従い、編集したファイルが `schema/` の JSON Schema に合うことを確かめます。
3. プルリクエストを出します。説明文には `card_id` か `set_code` を書いてください。スキーマや文書の変更では、設計を決めた Issue も示します。

## レビューで見る点

- 各値が、参照している`カード`の実物に載っている内容と合っていること。セット、名前、コスト、レアリティも含めます。
- 文字列が`カード`の実物に載っているとおりであること。空白や改行も変えません。
- 変更に含まれるすべてのファイルが、`schema/` の JSON Schema に合うこと。
- 新しい `card_id` が [design.md](design.md) のルールに従っていて、すでにあるものと重複しないこと。
- 公式の訂正による追記が `history` に足されること。過去の記録を書き換えないこと。
