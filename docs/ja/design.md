# 設計:mana-vault card-database

Translations: [英語](../en/design.md)

## ねらい

このデータベースは、Magic の各カードを正確にデータへ収めます。

収め方を決める前提は二つあります。

1. カードは、決して変わらない名前で識別します。
2. カードは、ルールで定められたものだけを持ちます。商品や言語に属する情報は、カードから
   分けて置きます。

## カード

Magic のルールでは、カードは、カード名・マナ・コスト・色・タイプ行・ルール・テキストからなる
ゲームのオブジェクトです。タイプ行は、特殊タイプ・カード・タイプ・サブタイプで構成されます。
カード・タイプに応じて、パワーとタフネス、忠誠度、バトルの守備値が加わります。ルールは、
1 枚のカードが複数の面や部分を持つことも認めています。

このデータベースは、ルールのコンポーネントの集まりを`カード`と呼びます。`カード`は構造だけを
持ちます。マナ・コストとタイプ行は、コンポーネントの一覧の値を id で指します。ルール・テキスト
は、ルールが名づける概念——能力、コスト、対象、効果——として収めます。`カード`は、どの言語の
文字も持ちません。紙が示す文字は、英語も含めて`print/<lang>/`の下に置きます。ただし
フレイバー・テキストは例外で、`プリント`に属します。

カードには`レイアウト`があります。多くのカードは普通の形ですが、両面カードや分割カード、
アドベンチャー・カードのように、面や部分を複数持つ形もあります。`カード`は、
`data/oracle/card/component/layout.json` の値の id で自分の`レイアウト`を指します。値の形は
`レイアウト`ごとに固まっていて、それぞれに専用のスキーマがあります。カードの登録は一度だけで、
後から id は変えません。

## プリント

同じカードでも、商品のなかでは同じ見え方とは限りません。セットはカードを再録し、言語ごとに
名前や文字が変わります。コラボ商品は、別の名前でカードを収めることもあります。カードが
1 つの商品に現れたときのことを、`プリント`と呼びます。

`プリント`は`カード`とは別に収録します。セット、コレクター番号、言語、出た媒体、レアリティ、
イラストレーター、画像の URL を記録し、その見え方のフレイバー・テキストを持ちます。再録が
フレイバー・テキストを変えることはあるので、この項目は`プリント`に属します。カードのどの
プリントでも同じ文字は、その言語のカードの脇に一度だけ置き、違う文字を示すプリントだけが自分の
ものを持ちます。

レアリティは`プリント`ごとに決まるので、カードのレアリティはプリントを並べて読みます。
フォーマットの可否はプリントから導いて、保存しません。common のプリントを持つカードは
パウパーで使用でき、フォーマットが禁止していなければ有効です。

## 原理

1. ルールのコンポーネントは一覧に置き、値ごとに id を持たせます。`カード`とプリントは、値の
   id で照会します。値が一度だけ収録され、値を訂正しても id は変わりません。
2. 導出できるものは保存しません。カードの色、フォーマットの可否、マナ記号が刷る表記
   （CR 107.4）などです。導出の元になるものは完全に保存します。全カードの全プリント、公式の
   訂正、禁止と制限のデータです。
3. 紙が刷る文字は、言語ごとにカードの脇に置き、`カード`と同じ id で対応させます。名前、
   タイプ行、ルール・テキストの文、コンポーネントの値のその言語のものです。
4. 公式の訂正は、値を直してその `history` に記録を追加します。過去の記録は決して書き換えず、
   データが持ってきた値はデータのなかに残ります。

## ディレクトリ構成

```text
data/
  oracle/
    card/
      component/
        layout.json
        color.json
        mana_symbol.json
        counter_type.json
        rarity.json
        type_line/
          supertype.json
          card_type.json
          subtype.json
        ability/
          ability_word.json
          keyword_ability.json
        action/
          keyword_action.json
      normal/li/lightning-bolt.json
    set/
      sta.json
  platform.json
  print/
    en/
      card/
        base/
          entity/li/lightning-bolt.json
          component/
            layout.json
            rarity.json
            ...
        fca/31.json
      set/
        base/sta.json
        sta/42.json
    ja/
      card/
        base/
          entity/li/lightning-bolt.json
          component/
            ...
        fca/31.json
      set/
        base/sta.json
        sta/105.json
```

変わらないデータと、紙そのものは分けて収録します。`data/oracle/` は`カード`とセットを構造として
収録し、どの言語の文字も置きません。`data/platform.json` は媒体の一覧です。`data/print/` は紙
そのもので、言語ごとにフォルダに分かれます。言語のフォルダに入るのは二つです。`card/` は
カードの文字で、`base/` にどのプリントも同じものを置き、違う文字を示すプリントはそのほかに自分の
ファイルを持ちます。`set/` はセットの名前を `base/` に置き、プリントをその中に収めます。

スキーマと各ファイルの細かい説明は、[schema.md](schema.md) に述べます。
