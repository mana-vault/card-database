# 設計:mana-vault card-database

## ねらい

このデータベースのねらいは、カードを、データセットとして正しく定義することです。

そのために、まず二つのことが必要です。

1. カードに名前を付け、安定して識別できるようにすること。
2. カードには、ルールが定める部品だけを持たせ、商品や言語の情報はカードの外に置くこと。

## 用語定義

### カード

Magic のルールは、カードがどのようなものかを定めています。カードは、カード名とマナ・コスト、色、タイプ行、ルール・テキストから成るゲームのオブジェクトです。タイプ行は、特殊タイプとカード・タイプ、サブタイプから成ります。カード・タイプによっては、パワーとタフネス、忠誠度、守備値が加わります。ルールはまた、両面カード、分割カード、出来事カード、バトルのように、一枚のカードが複数の面を持つことを認めています。

このデータベースでは、この部品の集まりを`カード`と呼びます。`カード`は、タイプ行とマナ・コストを部品ごとに持ちます。印刷された行から値を読み取らずに済むためです。`カード`の値は英語です。ゲームは Wizards of the Coast が作っており、英語が基準になるためです。部品の名前は、公式ルールの言葉に従います。商品や言語の情報は、`カード`に入りません。

`カード`には種類があります。通常のほか、変身する両面カードやモードを持つ両面カード、分割カード、出来事カード、バトルのように、複数の面を持つ種類があります。値の持ち方は、種類ごとに決まります。通常の`カード`は、部品の値を直に持ちます。複数の面を持つ種類では、面の名前の項目で面ごとの値を持ちます。持ち方を、種類の間で一つの形に共通化することはしません。それぞれの種類に、その持ち方のスキーマがあります。

`カード`は、一度登録したら同一性が変わらないものとして登録します。値が間違っていれば、見つかったときに直します。

### 翻訳

値の鋳型は英語です。どこかの言語で紙面に載る値は、`翻訳`として持ちます。`翻訳`は、値を持つ物と、その言語を組みにして一つのデータで、英語と違う値だけを書きます。紙面の値は、英語の値に、その言語の`翻訳`を重ねて組み立てます。

値を持つ物は、いまのところ二つあります。`カード`と、セットです。セットの名前(`魔法彷徨の艦`/Murders at Karlov Manor)も言語ごとに違うためです。

### プリント

商品の中では、同じカードがいつも同じ形で並ぶとは限りません。セットはカードを再録します。言語ごとに、紙面のカード名やテキストは異なります。コラボ商品は、カードを別名で載せます。`カード`が一つの商品の中に現れるものを、`プリント`と呼びます。

`プリント`は、`カード`とは別のデータとして持ちます。セットとコレクター番号、言語、レアリティ、アーティスト、画像 URL を持ちます。`プリント`は、自分の属する`カード`を id で指します。紙面に印刷された値は、`プリント`は持ちません。紙面の値は、`カード`の英語に、その言語の`翻訳`を足して組み立てます。

## ディレクトリ構成

```text
data/
  component/
    card_type.json
    subtype.json
    special_type.json
    color.json
    mana_symbol.json
  card/
    li/lightning-bolt.json
  translation/
    card/li/lightning-bolt/ja.json
    set/mh3/ja.json
  print/
    ja/mh3/170.json
  set/
    mh3.json
docs/
  en/…, ja/…
```

`data/component/` には、部品ごとに決まった値を、一覧のファイルとして置きます。一つの値は、id と、Wizards of the Coast が定めた英語の値を組みにして持ちます。

| 部品 | ファイル | 値の例 |
| --- | --- | --- |
| カード・タイプ | `card_type.json` | クリーチャー、インスタント、土地 |
| サブタイプ | `subtype.json` | 人間、オーラ、沼 |
| 特殊タイプ | `special_type.json` | 基本、伝説、世界 |
| 色 | `color.json` | 白、青、黒、赤、緑 |
| マナ記号 | `mana_symbol.json` | `{W}`、`{U}`、`{R}` |

中身が増えるのは、Wizards of the Coast が新しい値を定めたときだけです。

`data/card/` には`カード`を置きます。`カード`は、この一覧の値を id で参照して組み立てます。id は変えないため、値の訂正で、その値を指す`カード`が無効になることはありません。フォルダは、`card_id` の最初の二字で分けます。《稲妻》のファイルは `card/li/lightning-bolt.json` です。データの内容をフォルダの名前に出さず、どこに置くかだけを均一に伸ばすための分け方です。

`data/translation/` には`翻訳`を置きます。まず `card/` と `set/` に分けます。カードの`翻訳`は `data/card/` と同じ切り方で、`card_id` の最初の二字で分けます。《稲妻》の日本語の紙面の値は `translation/card/li/lightning-bolt/ja.json` です。セットの`翻訳`は `card_id` よりずっと少ないので、そのままセットごとのファイルにします。MH3 の日本語の値は `translation/set/mh3/ja.json` です。

`data/set/` にはセットの本体のファイルを置きます。一つのセット = 一つのファイルで、セットの少なさからハッシュで分散するまでもありません。MH3 は `set/mh3.json` です。

`data/print/` には`プリント`を置きます。`プリント`は、一つにつき一つのファイルで、フォルダは言語、さらにセットで分けます。MH3の日本語の170番の`プリント`は、`print/ja/mh3/170.json` です。紙面の値は、この層にありません。`カード`と`翻訳`の値から組み立てて使うためです。

セットの登録はここでととのいます。リポジトリのどこかで使われた `set_code` は、すべてセットのファイルとして登録します。

## スキーマ

各ファイルの中身は、[JSON Schema](https://json-schema.org/) の形式で書かれたスキーマで決めます。スキーマには、そのファイルが満たすべき値の形をすべて書いておくため、データがその形に照らして正しいかどうかを確かめられます。

スキーマのファイルは `schema` ディレクトリーに置き、その中は、`data` のディレクトリー構成に対応します。`data/component/` に対応するスキーマは `schema/component.json`、`data/card/` に対応するのは `schema/card/` で、`カード`の種類ごとに一つのファイルを持ちます。通常の種類は `schema/card/normal.schema.json` です。`翻訳`も同様に、種類ごとのスキーマを持ちます。`翻訳`の形は言語に寄らないため、言語でスキーマを分けることはしません。セットの`翻訳`は、カードの`翻訳`と対象が違うため、`schema/translation/set.schema.json` を持ちます。`プリント`とセットは `schema/print.json` と `schema/set.json` に対応します。

```text
schema/
  component.json
  card/normal.schema.json
  translation/normal.schema.json
  translation/set.schema.json
  print.json
  set.json
```

## 公式の訂正

カードに公式からテキストの訂正が入ったら、修正先のファイルのスキーマにしたがって、その物の `history` へ訂正の記録を追記します。追記の形をとるのは、直した値を書き換えることなく、過去の値のすべてがデータの中に見えるようにするためです。
